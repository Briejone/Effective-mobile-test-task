
# Effective Mobile DevOps Test Task

Простое веб-приложение на Python с reverse‑proxy через Nginx, запущенное в Docker‑контейнерах с помощью Docker Compose.

## 🚀 Быстрый старт

### 1. Клонируйте репозиторий
```bash
git clone <url-вашего-репозитория>
cd effective-mobile-test
```

### 2. Настройте переменные (опционально)
Создайте файл `.env` (можно скопировать из примера):
```env
NGINX_PORT=80
```
> Если порт 80 занят на хосте, измените на другой, например `8080`.

### 3. Запустите контейнеры
```bash
docker-compose up --build
```

### 4. Проверьте работоспособность
В другом терминале выполните:
```bash
curl http://localhost
```
Ожидаемый ответ:
```
Hello from Effective Mobile!
```

Если вы использовали другой порт для Nginx (например `8080`), то:
```bash
curl http://localhost:8080
```

## 🧱 Архитектура

```
Пользователь → localhost:80 (Nginx) → backend:8080 (Python HTTP server)
                                     ↑
                              внутренняя Docker-сеть
```

- **Nginx** принимает HTTP‑запросы на порту `80` (проброшенном на хост)  
- Проксирует все запросы на `backend` по имени сервиса и порту `8080`  
- **Backend** слушает только внутри Docker‑сети и недоступен напрямую с хоста  
- Оба контейнера общаются через изолированную сеть `app-network`

## 🛠 Используемые технологии

| Компонент     | Технология                      |
|---------------|----------------------------------|
| Backend       | Python 3.12 (http.server)       |
| Reverse proxy | Nginx (образ stable-alpine)     |
| Контейнеризация | Docker + Docker Compose v3.8   |
| ОС образов    | Alpine Linux (для Nginx), slim-образ Python |
| Управление конфигурацией | Переменные окружения (.env) |

## 📁 Структура проекта

```
.
├── backend/
│   ├── Dockerfile        # сборка образа Python (не-root пользователь)
│   └── app.py            # HTTP-сервер на порту 8080
├── nginx/
│   └── nginx.conf        # конфигурация reverse-proxy с proxy_pass
├── docker-compose.yml    # два сервиса, сеть, лимиты ресурсов
├── .env                  # переменные окружения (NGINX_PORT)
├── .gitignore
└── README.md
```

## ✅ Что сделано сверх обязательных требований (плюсы)

- Запуск backend **не от root** (создан пользователь `app`)
- Документирование порта через `EXPOSE` в Dockerfile
- Отдельная пользовательская сеть `app-network`
- Поддержка `.env` файла для гибкой настройки порта Nginx
- Передача заголовков прокси (`Host`, `X-Real-IP`, `X-Forwarded-For`) в Nginx
- Лимиты CPU и памяти через `deploy.resources`
- Healthcheck в backend (опционально — добавьте при желании)
- Логичные коммиты и `.gitignore`

## 🔍 Проверка изоляции

Backend **не должен быть доступен с хоста** напрямую. Убедиться в этом можно командой:
```bash
curl http://localhost:8080
```
(если порт 8080 не проброшен, команда завершится ошибкой — это правильно)

## 📦 Остановка и очистка

```bash
docker-compose down
```
